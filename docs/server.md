# Сервер

С 01.11.2026 — облачная платформа МГТУ TeraCloud (https://panel.teracloud.bmstu.ru, вход через SSO, из сети МГТУ или
через VPN). Прежний сервер (195.19.43.12) закрыт. Пространство `diplom`, профиль GPU Small; квоты проекта увеличены
06.11.2026: 2×V100 32 ГБ, 128 ГБ памяти, домашний каталог 100 ГБ (JuiceFS, сохраняется после остановки), `/shared` 10 ГБ,
доступ к Hugging Face. Корень контейнера (`/`, `/tmp`) стирается при остановке. Работа — через JupyterLab (терминал,
тетрадки); SSH — по ключу из панели («SSH-ключи», с 10.11.2026; раньше SSH не было). Python 3.11 и PyTorch с CUDA — в образе. Репозиторий —
https://github.com/doshik722/Presentation (открытый).

- Код — только на компьютере → push; на сервере `git pull`, ничего не правлю.
- Результаты (`runs/`) в git не идут — забираю через JupyterLab (правой кнопкой → Download) или архивом.
- Веса и кеш Hugging Face — в `~/hf` (`HF_HOME`), ответы Википедии — в `data/sources/wiki_cache`.
- Википедия (`ru.wikipedia.org`, `en.wikipedia.org`) открыта администратором 10.11.2026 (до этого прокси отвечал
  `403 Forbidden`). Запасной путь, если снова закроют, — туннель с компьютера автора, раздел «Туннель Википедии».
  Внешние API (судья) из пространства закрыты — судья работает на компьютере автора.
- Пароли и токены — не в репозиторий.

## Настройка пространства (один раз)

```
cd ~ && git clone https://github.com/doshik722/Presentation.git Diplom
cd Diplom && pip install --user -e ".[models,training,reward]" pytest "brotli>=1.2"
echo 'export HF_HOME=$HOME/hf' >> ~/.bashrc && source ~/.bashrc
python -c "from huggingface_hub import snapshot_download as s; print(s('t-tech/T-lite-it-2.1', allow_patterns=['*.json','*.safetensors','*.txt','*.model','*.jinja']))"
```

Пакеты — только с `--user` (в домашний каталог), иначе пропадут при остановке пространства. `brotli>=1.2` — новая
`huggingface_hub` распаковывает ответы с параметром, которого нет в `brotli` образа (`process() takes no keyword
arguments`). Ответы T-lite из EXP-010 и EXP-012 (`runs/variance/20261020_0331`, `runs/reward_sources/20261027_2150`)
перенесены архивом с компьютера.

## Запуск

```
cd ~/Diplom && git pull
nvidia-smi                                # какая карта свободна → CUDA_VISIBLE_DEVICES в тетрадке
cd notebooks && jupyter nbconvert --to script <тетрадка>.ipynb
nohup python -u <тетрадка>.py > $HOME/<тетрадка>.log 2>&1 &
tail -f $HOME/<тетрадка>.log              # Ctrl+C — выйти из просмотра, работа продолжается
```

Тетрадка запускается скриптом в фоне: закрытый браузер её не прерывает, ход — в журнале.

## Туннель Википедии (10.11.2026; запасной путь — Википедию открыли в тот же день)

Пока Википедия закрыта прокси пространства, запросы к ней идут через компьютер автора (по согласованию
с администратором). На компьютере: `scripts/wiki_tunnel/proxy.py` — прокси, который слушает только 127.0.0.1
и пропускает только `ru/en.wikipedia.org:443` (CONNECT, TLS сквозной); `tunnel.ps1` держит обратный SSH-проброс:
в контейнере открывается `127.0.0.1:18080`, ведущий к этому прокси, при обрыве — переподключение через 5 с, компьютер
не засыпает, пока скрипт работает. В коде Википедию ходит через `WIKI_PROXY` (`WikiClient`) — только она;
Hugging Face и pip — как обычно. При разрыве туннеля сетевые ошибки повторяются до 5 минут.

**Условие:** SSH-сессия должна попадать в тот же контейнер, где работает ядро JupyterLab (иначе порт откроется
не там). Проверка — ячейка «Проверка Википедии» в `grpo.ipynb`.

Один раз — вход по ключу (без пароля, иначе ночное переподключение встанет на запросе пароля), в PowerShell:
```
ssh-keygen -t ed25519            # Enter на все вопросы (или пароль ключа + служба ssh-agent и ssh-add)
type $env:USERPROFILE\.ssh\id_ed25519.pub
```
Строку из `.pub` (начинается с `ssh-ed25519`) — в панели TeraCloud, «SSH-ключи» → «Добавить ключ»; ключ
действует для запущенных пространств (добавление в работающее — до двух минут). Приватный ключ (`id_ed25519` без
`.pub`) остаётся только на компьютере. Адрес, порт и пользователь для SSH — в панели, на странице пространства.
Проверка с компьютера: `ssh -p <порт> <пользователь>@<адрес> echo ok` — без запроса пароля.

Каждый раз (окно PowerShell держать открытым; Ctrl+C — остановить):
```
powershell -ExecutionPolicy Bypass -File scripts\wiki_tunnel\tunnel.ps1 -Server <пользователь>@<адрес> -SshPort <порт>
```
В тетрадках (`grpo.ipynb`, `sft_eval.ipynb`) — `WIKI_PROXY = "http://127.0.0.1:18080"`; когда откроют белый
список — `""`. Журналы туннеля — `scripts/wiki_tunnel/tunnel.log` и `wiki_proxy.log` (в git не идут).

- Порт 18080 занят на сервере — другой порт и в `-Port`, и в `WIKI_PROXY`.
- Компьютер должен быть включён и в сети всё время прогона с поиском; закрытая крышка или выключение — обрыв.
  Уже полученные ответы лежат в кеше запуска, туннель нужен только для новых запросов.
- В манифест запуска пишется `wiki_proxy` каждой сессии — видно, какие прогоны шли через туннель.
