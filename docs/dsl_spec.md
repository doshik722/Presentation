# Спецификация DSL презентаций

Версия 0.1. Общие решения — в [decisions.md](decisions.md), раздел 2.

## 1. Общие правила

- Текст в UTF-8, строки разделяются `\n` (`\r\n` тоже принимается).
- Пустые строки и строки только с пробелами пропускаются и не считаются ошибкой.
- Строки-ограждения Markdown (```` ``` ````, ```` ```dsl ````, ```` ```text ````) пропускаются: модели часто так оборачивают ответ.
  Они не считаются ошибкой, но их число записывается в диагностику.
- Пробелы в начале и конце строки обрезаются.
- Каждая содержательная строка имеет вид `#ТЕГ: значение`.
  - Тег не зависит от регистра (`#title:` = `#TITLE:`).
  - Пробелы между тегом и двоеточием допускаются (`#TITLE :`), между `#` и тегом — нет.
  - У тегов со значением двоеточие обязательно.
- Одна строка — один элемент. Переносов значения на следующую строку нет.

## 2. Ошибки разбора

Ошибочная строка не попадает в презентацию; остальные строки разбираются как обычно.
Для каждой ошибки записываются номер строки, исходный текст, код и пояснение.

| Код | Когда возникает |
|---|---|
| `untagged` | строка не начинается с `#` |
| `unknown_tag` | тега нет в списке |
| `missing_colon` | у тега со значением нет двоеточия |
| `empty_value` | у тега со значением пустое значение |
| `outside_slide` | элемент (кроме `#PLAN`) стоит до первого `#SLIDE` |
| `duplicate_title` | второй `#TITLE` на одном слайде |
| `bad_value` | значение не соответствует синтаксису тега (раздел 4) |
| `too_long` | строка длиннее лимита |
| `limit_exceeded` | превышен лимит числа слайдов или элементов на слайде |

Элементы до первого `#SLIDE` не переносятся на слайд автоматически: так материал не попадает незаметно на чужое место.

## 3. Структура

- `#SLIDE` начинает новый слайд. Текст после `#SLIDE` (например, `#SLIDE 3`) молча игнорируется.
- На слайде ровно один `#TITLE`. Слайд без заголовка сохраняется с предупреждением `missing_title`.
- Слайд без заголовка, элементов, заметок и источников удаляется с предупреждением `empty_slide`.
  Слайд только с заголовком сохраняется: это может быть разделитель раздела.
- `#PLAN` допускается где угодно; сборщик его пропускает, в метриках полноты он не учитывается.
- Несколько `#NOTES` на одном слайде склеиваются.
- Лимиты (задаются в конфигурации): слайдов — 30, элементов на слайде — 20, длина строки — 1000 символов.
- Обрыв генерации по лимиту токенов — свойство всего ответа, а не строки: среда записывает его
  в метаданные ответа (`truncated: true`), парсер его не отмечает.

**Ошибка и предупреждение.** Ошибочная строка теряется и снижает `parse_rate`.
Предупреждение означает, что содержимое сохранено, но в презентации есть дефект; на `parse_rate` оно не влияет,
но может учитываться наградой. Предупреждения:

| Код | Когда возникает |
|---|---|
| `missing_title` | у слайда нет `#TITLE` |
| `empty_slide` | пустой слайд удалён |
| `quote_without_attribution` | у `#QUOTE` нет автора и источника |
| `unknown_key` | в `#CHART`, `#PLOT` или `#DIAGRAM` есть неизвестный ключ; он пропущен |

Парсер сохраняет все корректные элементы. Ограничения по визуалу применяет сборщик:
на слайде рисуются первые 2 крупных визуальных элемента (`#CHART`, `#PLOT`, `#DIAGRAM`, `#TIMELINE`, `#IMAGE`)
и первые 3 формулы; лишние попадают в отчёт сборщика как `overflow` и учитываются наградой.

## 4. Теги и синтаксис значений

### Текстовые

| Тег | Значение |
|---|---|
| `#TITLE` | свободный текст |
| `#TEXT` | абзац связного текста; несколько `#TEXT` подряд — несколько абзацев |
| `#BULLET` | пункт списка: только для настоящих перечислений однородных пунктов |
| `#NOTES` | свободный текст |
| `#PLAN` | свободный текст: план, причина вызова инструмента; на слайды не попадает |
| `#SOURCE` | id статьи (`d12`) или раздела (`d12#3`) из результатов инструментов этого эпизода, см. ниже |

`#TEXT` и `#BULLET` различаются по смыслу: рассуждение, где каждая фраза опирается на предыдущую,
пишется абзацами `#TEXT`; однородные пункты, которые можно переставить без потери смысла, — списком `#BULLET`.
На одном слайде их можно сочетать. Уместность выбора оценивает судья в критерии «структура», а не парсер.

### `#QUOTE`

`текст цитаты — автор, источник`

Цитата и атрибуция делятся по **последнему** вхождению ` — ` (длинное тире с пробелами; ` -- ` тоже принимается).
Без атрибуции цитата сохраняется с предупреждением `quote_without_attribution`.

### `#FORMULA`

LaTeX без ограничителей: `\theta_{t+1} = \theta_t - \eta \nabla L(\theta_t)`.
Ограничители `$...$`, `$$...$$`, `\(...\)` снимаются. Парсер синтаксис LaTeX не проверяет:
формула корректна, если её удалось отрисовать (ошибку фиксирует сборщик как `render_error`).
Рисует matplotlib mathtext — подмножество LaTeX, а не полный LaTeX: внешний LaTeX не нужен,
проект ставится одной командой pip. Перед отрисовкой переписываем правильный LaTeX, которого
нет в mathtext (`rendering/mathtext.py`):

| Пишет модель | Рисуем как |
|---|---|
| `\le`, `\ge`, `\implies`, `\iff`, `\gets`, `\land`, `\lor`, `\lnot` | `\leq`, `\geq`, `\Rightarrow`, `\Leftrightarrow`, `\leftarrow`, `\wedge`, `\vee`, `\neg` |
| `\tfrac`, `\cfrac`, `\stackrel`, `\operatorname*` | `\frac`, `\frac`, `\overset`, `\operatorname` |
| `\textbf`, `\textit`, `\textrm`, `\emph`, `\mbox` | `\text` |
| `\lvert`, `\rvert` (модуль); `\lVert`, `\rVert` (норма) | `|`; `\|` |
| `\displaystyle`, `\limits`, `\big` и родственные, `\tag{…}`, `\color{…}`, `\boxed{…}` | удаляем, содержимое `\boxed` оставляем |
| `\xrightarrow[снизу]{сверху}`, `\xleftarrow` | `\overset` / `\underset` над длинной стрелкой |
| `\pmod{N}`, `\bmod`, `\mod` | `\;(\mathrm{mod}\;N)`, `\;\mathrm{mod}\;` |
| `cases`, `dcases` | фигурная скобка и строки друг под другом |
| `aligned`, `align`, `gathered`, `gather`, `split` | строки друг под другом, без выравнивания по `&` |

Не переписываем и считаем `render_error`: матрицы (`pmatrix`, `bmatrix` …), химию mhchem (`\ce{…}`;
химические формулы пишем как `6\text{CO}_2`), `\underbrace`, `\overbrace`.

Сломанной считаем формулу, на которой mathtext падает, и формулу, в которой хотя бы один символ
нарисован заглушкой (например, `x^\text{\textasciicircum}2`: внутри `\text{}` `\t` читается как табуляция).

### `#CHART`

Пары `ключ=значение` через `;`, элементы списков — через `,`, дробная часть чисел — через точку.

| Ключ | Обязателен | Значение |
|---|---|---|
| `type` | да | `bar`, `line` или `pie` |
| `x` | да | подписи категорий |
| `y` | да | числа |
| `title` | нет | заголовок графика |
| `unit` | нет | единица измерения значений |

Проверки: длины `x` и `y` совпадают; от 2 до 12 точек; все `y` — конечные числа; для `pie` все `y` ≥ 0 и сумма > 0.
Символы `;` и `=` внутри значений не поддерживаются. Неизвестные ключи пропускаются с предупреждением.
Ось X — всегда категории: для числовых зависимостей используется `#PLOT`.

### `#PLOT`

`y = выражение; x=a..b; title=...`

- Выражение: числа, `x`, `+ - * / ^`, скобки, функции `sin cos tan exp log sqrt abs`, константы `pi`, `e`.
- Знак умножения можно опускать: `0.15x`, `3sin(x)`, `2(x+1)`, `x(1-x)`. `2e-3` — число, а не `2*e - 3`.
- Выражение разбирается безопасно, без выполнения произвольного кода.
- `x=a..b` обязателен, `a < b`. `title` необязателен.

### `#DIAGRAM`

Два типа, до 8 узлов. Подписи узлов и стрелок не должны содержать `->`, `>`, `|`, `;` и `,`.

- Поток: `type=flow; A -->|подпись| B -> C; C -> A`
  - цепочки разделяются `;`, стрелка — `->` или `-->`;
  - подпись стрелки — в стиле Mermaid: `-->|текст|`;
  - ветвления и слияния задаются несколькими цепочками: `Причины -> Экономика; Причины -> Армия; Экономика -> Реформа; Армия -> Реформа`;
  - узлы с одинаковой подписью — один и тот же узел.
- Дерево: `type=tree; Корень > Потомок 1, Потомок 2; Потомок 1 > Внук 1, Внук 2`.

Схема рисуется редактируемыми фигурами PowerPoint: поток — послойно слева направо (стрелки назад — дугой),
дерево — уровнями сверху вниз. Содержательность схемы (ветвления, подписи стрелок, отсутствие дословного
повтора пунктов слайда) оценивает награда, а не парсер.


### `#TIMELINE`

`дата — событие; дата — событие`

От 2 до 8 пунктов через `;`. Дата и событие делятся по первому ` — `.
Дата — свободная строка («1861», «1860-е», «март 1917»). Порядок сохраняется как написан.

### `#IMAGE`

Описание нужной картинки свободным текстом, на обоих этапах. Модель картинок не видит и не выбирает:
по описанию сборщик ищет кандидатов в Wikimedia Commons и выбирает лучший через CLIP. Если сходство ниже порога,
ставится заглушка, а в отчёт сборщика пишется статус «не найдено».

### `#SOURCE`

Значение — id из результатов инструментов этого эпизода:
- `d12` — статья целиком; допустим, если статья была в выдаче `search`;
- `d12#3` — раздел 3 статьи 12 (`d12#0` — введение); допустим, если статья открыта через `open` или раздел прочитан
  через `read`.

URL и названия модель не пишет: по id система берёт из сохранённых ответов Википедии название статьи, заголовок
раздела, URL и номер правки. Парсер id не проверяет (он не знает, что было в эпизоде): id, которого не было
в результатах инструментов, сборщик пропускает и записывает в отчёт как `bad_source`; без инструментов
(«Поиск: нет») любой `#SOURCE` — `bad_source`. Если пользователь не хочет источников на слайдах, сборщик
проверяет id как обычно, но на слайды их не выводит (`show_sources=False`); модель об этом не знает. На одном слайде может быть несколько строк `#SOURCE`.
Номера источников сквозные, по порядку первого появления; одна ссылка — один номер.

Оформляет источники сборщик, а не модель:
- на слайде — одна строка мелким шрифтом: «Источник: <статья>, раздел „<раздел>“ (Википедия)», ссылкой на раздел;
- если источников больше двух или строка не помещается — номера («Источники: 1, 2»),
  а полный список — на автоматическом последнем слайде «Источники» (добавляется, только если где-то стоят номера;
  в отчёте сборщика — `sources_slide`, в число слайдов для метрик не входит).

## 4а. Ответ с вызовами инструментов

На этапе B модель может вызывать инструменты в любом месте генерации, в штатном формате вызова инструментов модели.
Парсер получает всё, что написала модель, по порядку, без блоков вызовов и без результатов инструментов.
Пояснение или план перед вызовом пишется тегом `#PLAN`; текст без тега — ошибка `untagged`, как обычно.

## 5. Диагностика разбора

- **Содержательные строки** — непустые строки, кроме ограждений Markdown и `#PLAN`.
- `parse_rate` = корректные содержательные строки / все содержательные строки. Если содержательных строк нет — 0.
- Отдельно записываются: число ограждений, предупреждения, число слайдов до и после удаления пустых.
