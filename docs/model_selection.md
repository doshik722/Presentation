# Выбор базовой модели

Это проект протокола. Код сценария удалён; выполнение эксперимента пока недоступно.

Выполняем сценарий в `src/presentation_rl/experiments/model_selection.py`.
Меняем список кандидатов и условия в `configs/experiments/model_selection.yaml`.
Анализируем сохранённые результаты в `notebooks/analysis.ipynb`.

Начинаем с одинаковых текста задания, аудитории, ограничений, исходных материалов
и настроек генерации. Допускаем разные штатные chat template и токенизаторы, иначе
могли бы сломать ожидаемый моделью формат. Сохраняем реальную ревизию модели.
Перед основным экспериментом заменяем `revision: main` в конфигурациях на проверенные
commit ID из результатов, чтобы обновление репозитория не изменило условия.

Получаем от каждой модели исходный текст ответа. По контракту это текст в DSL
([dsl_spec.md](dsl_spec.md)). Парсер разбирает его построчно, сборщик создаёт PPTX из корректных строк;
ошибки разбора и отрисовки сохраняются вместе с исходным ответом, без скрытого исправления другой моделью.
Записываем метрики и выдаём `review.yaml` для ручной оценки. Не делаем выводов по одной удачной попытке.

В каркасе предоставляем 3 задания × 2 модели × 2 seed = 12 попыток. Это отладочный
набор, а не достаточная доказательная база. Расширяем его до 20–30 репрезентативных
заданий, затем проверяем несколько seed на финалистах. Сравниваем пары результатов
на одинаковых заданиях и публикуем разброс, долю ошибок и число измерений.
Отделяем набор выбора модели от итогового test для PPO/GRPO.

Сначала проводим одношаговую генерацию без инструментов. Затем отдельно
сравниваем ответы с одинаковым фиксированным пакетом материалов. Не называем
этот этап исследованием самостоятельного интернет-поиска: для него ещё реализуем среду.
Для первой реализации запланирован только `resource_mode: disabled`; фиксированные материалы
добавляем в поле `source_packet` задания, а режимы cached/live реализуем позднее.

Рассматриваем крупную модель с ошибкой памяти как неподходящую для данной
конфигурации оборудования, а не как модель с доказанно низким качеством знаний.
Не смешиваем показатели скорости на разных GPU в одну сравнительную строку.

После реализации сценария сначала проверим план без загрузки моделей,
затем выполним генерацию. Сохранённые ответы будут оцениваться повторно
без новой генерации при изменении анализа или заполнении ручной разметки.
